### 1.4 Money/cash invariants to re-derive on the server (test these)

- `InvoiceTotals` is the ONLY totals algorithm (largest-remainder discount pro-rating, `Money.ApplyPercent`). Server recomputes; a mismatch with a client-supplied total is **ignored** (never trusted). `INVOICE_TOTAL_MISMATCH` only when the payload is internally inconsistent.
- Posted invoice immutable (`INVOICE_IMMUTABLE`) → corrections via void/refund/line.return compensating records.
- Payment idempotency by `OperationId` (`PAYMENT_DUPLICATE_OPERATION`), `PAYMENT_EXCEEDS_DUE`. At most one financial effect per command (intake `Settled` row + effect share one transaction).
- Document numbers server-authoritative & gapless-per-commit (race-safe via `ON CONFLICT`).
- Cash: one open session per (tenant,user) (`CASH_SESSION_ALREADY_OPEN`); close requires zero unsettled commands (`CASH_SESSION_UNSETTLED_COMMANDS`, evaluated vs `CommandIntake` where `Status<>Settled`); variance note rule (`CASH_VARIANCE_NOTE_REQUIRED`). `CashSessionClosedEvent` → ledger posting in **S10** via `IDomainEventDispatcher`.
- **Error codes:** reuse existing where present; ADD any missing (`INVOICE_TOTAL_MISMATCH`, `INVOICE_IMMUTABLE`, `PAYMENT_DUPLICATE_OPERATION`, `PAYMENT_EXCEEDS_DUE`, `CASH_SESSION_ALREADY_OPEN`, `CASH_SESSION_UNSETTLED_COMMANDS`, `CASH_VARIANCE_NOTE_REQUIRED`) inside a NEW `#region S09` in `ErrorCodes` — **first `grep -n "INVOICE_IMMUTABLE\|PAYMENT_DUPLICATE" src/Animora.Domain/Results/ErrorCodes.cs`**; many may already exist from Track A. Never rename/remove existing.

## 0) وضعیت پروژه و مرز کار (قبل از هر کاری بخوان — ۶۰ ثانیه)

- **محصول:** Animora — اپ دسکتاپ مدیریت و حسابداری کلینیک دامپزشکی. فارسی/RTL، تقویم جلالی.
- **استک:** یک Solution سی‌شارپ روی **.NET 10**، UI با **Avalonia + MVVM (CommunityToolkit.Mvvm)**، دیتابیس محلی **SQLite** (EF Core). آفلاین‌فرست، بدون سرور.
- **جریان داده (قانون معماری حاکم بر هر تغییر):**
  `View → ViewModel → اینترفیس Animora.Contracts (از طریق DI سازنده) → پیاده‌سازی واقعی Animora.Client.Services → dispatch در Animora.Application → Animora.Domain / Animora.Persistence.Sqlite (SQLite محلی)`
  - ViewModelها فقط به اینترفیس‌های `Contracts` وابسته‌اند؛ هرگز به سرویس concrete، تایپ EF/SQL یا scopeِ DI.
  - هیچ داده نمونه/seed و هیچ شاخهٔ `if(design-time)` داخل `Pages/**` نباید باشد.
  - ثبت سرویس‌ها و ViewModelها در `src/Animora.Desktop/App.axaml.cs` انجام می‌شود (composition root / DI).
- **وضعیت بک‌اند:** Track C کامل شده؛ Appointments (فاز C04) روی بک‌اند واقعی سوار است. سرور/Datasync (Tracks D–E) هنوز وجود ندارد و **جزو این پلن نیست**.
- **مرز صریح پلن (مهم):** هر چیزی که به «سرور / sync آنلاین / فازهای آیندهٔ رودمپ بک‌اند» مربوط است **خارج از این پلن** است و نباید به‌عنوان باگ یا تسک دیده شود. محصول فعلی local/offline-first است.
- **نسخهٔ مبنا:** این پلن روی `commit a1002d0` نوشته شده؛ شماره‌خط‌ها به همین نسخه اشاره دارند. اگر فایلی جابه‌جا شده، با نام نماد (symbol) جست‌وجو کن.

## 1) قوانین حاکم بر همهٔ تسک‌ها (بدون استثنا)

1. **بررسی هدفمند:** فقط فایل‌ها/خطوط ذکرشده در تسک را باز کن. بررسی بیهوده و grep کور ممنوع. اطلاعات لازم در خود تسک آمده تا بدون کاوش دوباره، مستقیم پیاده‌سازی را شروع کنی.
2. **کیفیت و استاندارد:** کد باید با معماری و قانون جریان داده (بخش ۰) هماهنگ باشد؛ هیچ چیز اضافی، فقط استاندارد و بهینه. بدون نشت EF/SQL به Desktop. ViewModel فقط Contracts.
3. **بدون تست سنگین:** گرفتن Full test / Full solution build / تست طولانی **ممنوع** است. فقط build سریع Desktop: `scripts/sandbox/build.sh` (باید 0 warning / 0 error باشد). اگر startup/DI/Shell را دست زدی، smoke: `scripts/sandbox/run.sh` (باید `SMOKE RUN OK` چاپ کند). تست واحد فقط اگر در خود تسک صریحاً خواسته شده و فقط همان کلاس هدف.
4. **قانون پوش (اجباری):** در انتهای هر تسک — و همچنین هرجا وسط تسک یک فیکس سنگین/حجیم انجام شد — باید با اسکریپت پوش، کامل push شود:
   ```bash
   scripts/git/push.sh "type(scope): پیام دقیق و قابل‌درک"
   ```
   این اسکریپت: `add -A` → `commit` → `fetch` + `rebase --autostash` → `push`. اگر exit code = `3` شد (نبود credential)، ابزار `setup_github_environment` را یک‌بار صدا بزن و دوباره اجرا کن.
5. **تیک‌زدن:** پس از اتمام هر تسک، در همین فایل بخش «وضعیت تسک‌ها» را به ✅ تغییر بده و چک‌باکس‌های داخل فایل همان تسک را تیک بزن. سپس push کن.
6. **بودجهٔ توکن/زمان:** کمترین بررسی، بالاترین کیفیت. تفکر لازم از قبل در تسک‌ها انجام و نتیجهٔ خالص نوشته شده؛ دوباره‌کاریِ تحلیل ممنوع.
7. **تسک پایانی (پاک‌سازی):** پس از اتمام هر ۵ تسک، به‌عنوان آخرین کار **فقط فایل‌های داخل `Plan/` حذف شوند** (این فایل + ۵ تسک). به هیچ فایل دیگر و فایل رودمپ دست نزن. سپس push نهایی.
8. **عدم تداخل:** هر تسک روی مجموعهٔ مشخصی از فایل‌ها کار می‌کند؛ ترتیب پیشنهادی ۱→۵ است چون تسک‌های بعدی روی خروجی تسک‌های قبلی (مخصوصاً قرارداد وضعیت و نگاشت) تکیه دارند. اگر موازی اجرا شد، به «وابستگی‌ها» در ابتدای هر تسک توجه کن.
